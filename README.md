# 课程互认公告镜像与夜间交割

**数据工程 · 数仓与数据湖。** 将院校逐版发布的课程互认公告摄入 SQLite，按就读日还原当时适用的参考数据；并在只追加的公告镜像之上实现中央回溯补发、夜间分批交割与双时间轴查询。本项目不办理学生申请，也不处理个人信息。

在仓库根目录以 Python 3.9+ 运行，无第三方依赖：

```sh
# 基础镜像：导入公告、按就读日查询
python3 -B -m articulation --db demo.sqlite apply examples/opening.json
python3 -B -m articulation --db demo.sqlite lookup BAY-FIELD HIS-17 2025-12-31
python3 -B examples/smoke.py

# 夜间交割全流程演练（授权 → 补发 → 分批收件 → 激活 → 双时间轴/溯源）
python3 -B examples/settlement.py
```

## 夜间交割命令一览

| 命令 | 作用 |
| --- | --- |
| `authorize <json>` | 登记院校获准的课程范围 |
| `reissue <json>` | 受理中央回溯补发（改正历史生效日、改原公告行、补历史空段） |
| `open-series <json>` | 开设夜间交割系列（delta 小包 / full 整份重交，按记录数给额度） |
| `receive <json>` | 收件并核验单个交割包（重复收件幂等，迟到包可重放） |
| `activate <院校> <系列>` | 基底齐全后切换到柜台可用目录 |
| `status <院校>` | 查询已交割状态、包状态与未生效阻塞原因 |
| `lookup <院校> <课程> <就读日>` | 当前视角的日常柜台答案 |
| `lookup-as-of <院校> <课程> <就读日> <UTC时刻>` | 按旧发布状态重查当时答复 |
| `lineage <院校> <课程>` | 新旧公告行溯源（含来源改变、结论未变的记录） |

## 关键语义

- 补发只替换它点名的历史 `(院校, 版, 课程)` 行，后来独立发布的变更不会被覆盖；若修正使后续撤回失去前提，整份补发拒绝，不进入当前目录。
- 收件、核验、柜台切换是三件事：半批未齐时继续答旧目录，整份重交不得覆盖交割期间校方确认过的新版。
- 额度按材料记录数计算；delta 可在基底确认后只交更小的更正包，full 重交完整范围但占用更多额度。
- 当前视角与系统时刻视角共用同一份已激活补发集合，迟到回执、重复收包和后续新更正之后，柜台答案与中央交割状态始终对得上；未生效时明确说明是缺批、范围未授权还是补发本身未生效。

字段与持久化语义见 [PROJECT_SPEC.md](PROJECT_SPEC.md)，补发样例见 [examples/reissue-2026-01.json](examples/reissue-2026-01.json)。
